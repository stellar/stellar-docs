These are result codes that communicate success (200) or failure (400) specific to the `Payment` operation, which often fails because the receiving account does not trust the issuer of the asset being sent.

Learn more about the [`Payment` operation](../../../../../../../learn/fundamentals/transactions/list-of-operations#payment).

<ResponseField name="OpSuccess" type="PAYMENT_SUCCESS">
  The payment was successfully completed.
</ResponseField>

<ResponseField name="OpMalformed" type="PAYMENT_MALFORMED">
  The input to the payment is invalid.
</ResponseField>

<ResponseField name="OpUnderfunded" type="PAYMENT_UNDERFUNDED">
  The source account (sender) does not have enough lumens to send the payment amount while maintaining its own minimum reserve.
</ResponseField>

<ResponseField name="OpSrcNoTrust" type="PAYMENT_SRC_NO_TRUST">
  The source account does not have a trustline for the asset it is tring to send.
</ResponseField>

<ResponseField name="OpSrcNotAuthorized" type="PAYMENT_SRC_NOT_AUTHORIZED">
  The source account is not authorized to send this asset.
</ResponseField>

<ResponseField name="OpNoDestination" type="PAYMENT_NO_DESTINATION">
  The destination account does not exist.
</ResponseField>

<ResponseField name="OpNoTrust" type="PAYMENT_NO_TRUST">
  The destination account does not have a trustline for the asset being sent.
</ResponseField>

<ResponseField name="OpNotAuthorized" type="PAYMENT_NOT_AUTHORIZED">
  The destination account is not authorized to hold this asset.
</ResponseField>

<ResponseField name="OpLineFull" type="PAYMENT_LINE_FULL">
  The destination account (receiver) does not have sufficient limits to receive amount and still satisfy its buying liabilities.
</ResponseField>

<ResponseField name="OpNoIssuer" type="PAYMENT_NO_ISSUER">
  The issuer of the asset does not exist.
</ResponseField>
