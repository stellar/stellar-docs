# Contributing to the Anchor Platform Documentation

This guide supplements the repository-wide
[contribution guide](../../../CONTRIBUTING.md) with the paths and generation
steps specific to Anchor Platform documentation.

Docusaurus excludes `**/CONTRIBUTING.md` files from the published site, so this
file is guidance for contributors browsing the repository. Anchor Platform
documentation is not separately versioned and is built by the site's main docs
plugin at `/docs/platforms/anchor-platform`.

## Where to Make Changes

| Content                  | Source                                                                                     | Generated output or configuration                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Guides and landing pages | `docs/platforms/anchor-platform/**/*.mdx`                                                  | Published directly by Docusaurus                                                                                                 |
| REST API definitions     | `openapi/anchor-platform/main-platform.yaml`, `main-callbacks.yaml`, and shared YAML files | Bundled specs in `openapi/anchor-platform/bundled-*.yaml`; generated pages under `docs/platforms/anchor-platform/api-reference/` |
| Platform RPC definitions | `openrpc/src/anchor-platform/**/*.json`                                                    | `docs/platforms/anchor-platform/api-reference/platform/rpc/anchor-platform.openrpc.json`                                         |
| RPC method pages         | `docs/platforms/anchor-platform/api-reference/platform/rpc/methods/*.mdx`                  | Published directly by Docusaurus using the generated OpenRPC specification                                                       |
| Sidebar structure        | Page and directory metadata, plus `config/anchorPlatform.sidebar.ts`                       | Anchor Platform sidebar on the site                                                                                              |

## Edit Documentation Pages

Edit prose in `docs/platforms/anchor-platform/`:

- `README.mdx` is the Anchor Platform landing page.
- `admin-guide/` contains operating and configuration guidance.
- `sep-guide/` contains guidance organized by Stellar Ecosystem Proposal (SEP).
- `api-reference/` contains a mixture of generated API content and manually
  maintained landing or RPC method pages. Check the file type and the workflows
  below before editing it.

Follow the repository's
[content conventions](../../../CONTRIBUTING.md#content-conventions). In
particular, link to other documentation using a path relative to the current
source file and include the `.mdx` extension:

```md
[Anchor Platform overview](./README.mdx)
[Learn about anchors](../../learn/fundamentals/anchors.mdx)
```

Do not use published `/docs/...` routes for internal documentation links.
Docusaurus validates relative source links during the build.

The sidebar is autogenerated from the Anchor Platform directory. Set page
ordering and labels in MDX front matter or directory metadata; only change
`config/anchorPlatform.sidebar.ts` when the top-level sidebar structure itself
needs to change.

## Update the OpenAPI Reference

The Platform API and callback API reference pages are generated. Do not edit
generated `*.api.mdx` files or their supporting generated JSON files directly.

1. Edit `openapi/anchor-platform/main-platform.yaml` or `main-callbacks.yaml`,
   plus `schemas.yaml` and `examples.yaml` when shared components need to
   change.
2. From the repository root, rebuild all OpenAPI documentation:

   ```bash
   pnpm api
   ```

3. Review the diff. Commit the source YAML, updated `bundled-*.yaml`
   specifications, and corresponding generated files together. Investigate
   unrelated generated changes instead of including them automatically.

The OpenAPI configuration and source-to-output mappings live in
`docusaurus.config.ts`; the Redocly entry points live in `redocly.yaml`.

## Update the Platform RPC Reference

The Platform RPC specification is assembled from the JSON files in
`openrpc/src/anchor-platform/`. Do not edit generated `*.openrpc.json` files
directly.

1. Edit the appropriate source files under `contentDescriptors/`, `examples/`,
   `methods/`, or `schemas/`.
2. If you add or remove a method, also add or remove its MDX page under
   `docs/platforms/anchor-platform/api-reference/platform/rpc/methods/`. These
   small pages select a method from the generated specification and render it
   with the `RpcMethod` component.
3. Build and validate the OpenRPC specifications:

   ```bash
   pnpm rpcspec:validate
   ```

4. Commit the OpenRPC source changes, any method-page changes, and the
   regenerated
   `docs/platforms/anchor-platform/api-reference/platform/rpc/anchor-platform.openrpc.json`
   together.

See [`openrpc/README.md`](../../../openrpc/README.md) for the OpenRPC object
structure and `$ref` conventions.

## Validate the Changes

Run the checks relevant to your change from the repository root:

```bash
pnpm check:mdx          # Markdown and MDX formatting
pnpm api                # Required after OpenAPI source changes
pnpm rpcspec:validate   # Required after OpenRPC source changes
pnpm build              # Full site build and internal-link validation
```

Before committing generated documentation, inspect `git diff` and make sure the
change contains its source files and only the expected generated output.
