Bridges and messaging layers that connect different blockchains.

## [Axelar](https://www.axelar.network)

Axelar Network is the universal interoperability network that securely connects all blockchain ecosystems, applications, assets, and users.

Get set up to write cross-chain smart contracts on Stellar using Axelar in the following guides.

### Learn about the Stellar GMP contracts

General Message Passing (GMP) is a cross-chain communication protocol that allows smart contracts on different blockchains to communicate with each other. With GMP, Stellar contracts can:

- Send messages to contracts on other chains like Ethereum, Avalanche, Base, Polygon, etc.
- Receive and process messages from contracts on other chains.
- Execute cross-chain operations securely and efficiently.

[Dive into Stellar GMP documentation →](https://docs.axelar.dev/dev/general-message-passing/stellar-gmp/intro)

### Learn about the Stellar Interchain Token Service (ITS)

The Interchain Token Service (ITS) enables tokens to scale across multiple chains by supporting both existing and newly minted tokens, preserving native-like fungibility and functionality on connected EVM chains, and automating deployment and maintenance to help teams easily manage supply on an open, scalable, and secure network. For the Stellar ecosystem, ITS offers:

- Creation of new tokens that can exist on multiple blockchains.
- Connecting existing Stellar tokens to other blockchain ecosystems.
- Secure transfers of tokens between Stellar and other chains.

[Learn how to use Axelar's ITS with Stellar →](https://docs.axelar.dev/dev/send-tokens/stellar/intro)

## [SODAX](https://www.sodax.com)

SODAX is an intent-based execution and liquidity system that connects Stellar with 20+ other networks, including Ethereum, Arbitrum, Base, BNB Smart Chain, Avalanche, Solana, Sui, and Bitcoin. A user signs one transaction on Stellar that states the outcome they want, independent solvers quote and fill it, and SODAX coordinates settlement through a hub on Sonic. The protocol is non-custodial: it routes and settles, and solvers fill.

From Stellar, applications can:

- Trade XLM and supported Stellar assets for assets on other networks, and the reverse, with status tracking until the intent settles.
- Supply and borrow through a cross-network money market, with XLM supported as collateral.
- Move supported assets between Stellar and other networks.

Stellar-specific handling in the SDK:

- **Trustlines**: when Stellar is the source network, the SDK's allowance and approval methods create the required trustline. When Stellar is the destination, `sodax.spoke.stellar.hasSufficientTrustline` and `requestTrustline` check and establish it before delivery.
- **Sponsored account activation**: a new Stellar account with 0 XLM can be activated with the base reserve paid by a SODAX sponsor account, so it can receive assets straight away. This uses the Sponsoring API (API key on request) or the `useStellarGate` hook in `@sodax/dapp-kit`.

SODAX can be integrated through the open-source TypeScript SDK (`@sodax/sdk`), the REST API at `api.sodax.com`, the `@sodax/dapp-kit` React hooks, or the Builders MCP server for AI coding agents.

[Read the SODAX quickstart →](https://docs.sodax.com/quickstart)

[Learn about Stellar trustlines in SODAX →](https://docs.sodax.com/developers/how-to/stellar_trustline)

[Learn about sponsored Stellar account activation →](https://docs.sodax.com/developers/how-to/stellar-sponsoring-getting-started)
